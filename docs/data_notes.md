## Local loading

The scripts and notebooks run without downloads. The Telco loader reconstructs a 21-column source view from the included cleaned snapshot and restores TotalCharges to missing for its 11 zero-tenure, zero-charge rows. The support loader selects the available 14 source-schema fields from the reduced working table. These are reconstructed working views, not newly retrieved raw datasets.

If exact original source CSVs are available, place them under data/raw using WA_Fn-UseC_-Telco-Customer-Churn.csv and customer_support_tickets.csv. The loader prefers these local files. Support identity fields and ticket descriptions are still excluded, and resolution text is reduced to a missing/present marker. The data/raw folder is ignored by Git.

## Field interpretation

Churn_binary is 1 for Yes and 0 for No. Numeric indicators in the model-ready snapshot were standardized by the original feature script, so they are not necessarily stored as 0/1. Boolean one-hot columns remain boolean.

The high-charge indicators use the full-dataset medians in the historical workflow. Tenure is not a calendar observation date. TotalCharges is accumulated spending, not projected lifetime value.

response_time_hours is purchase-to-first-response time, not time from ticket creation. resolution_time_hours is first-response-to-resolution time after excluding reversed intervals. The supplied table flags 1,365 reversed records. Its maximum valid resolution interval is about 23.47 hours, so is_long_resolution is always zero. Missing intervals and satisfaction scores also map to zero in certain historical boolean flags, so their missingness must be considered separately.

The label Invalid Time Record = Valid only means the code did not detect reversed timestamps. Rows with missing timestamps also receive that label; interval analysis still needs a non-missing interval check.

## Metadata tables

docs/telco_feature_dictionary.csv translates the original 42-entry dictionary and adds the two other predictors present in the supplied matrix: tenure_group_25-48 months and monthly_charge_group_Very High. Definitions describe variables before standardization. docs/model_evaluation_metrics.csv contains the supplied English metric definitions.

The support feature dictionary in docs/support_ticket_feature_dictionary.csv covers all 36 engineered support features. It extends the 31-entry dictionary generated by the supplied script with the four individual priority flags and satisfaction_group.

## Week 7 and Week 8 additions

The original fitted model bundle is in models. The supplied Week 7 scorecard has 7,043 rows and seven columns and is preserved under results/reported/week7. Its probabilities are rounded to four decimals, and customer_index is the original zero-based row position.

The Week 8 archive supplies a customer-level segmentation table, algorithm comparison, K-Means summary, nine-cell risk/value matrix, all contribution-ranked groups, and the three groups crossing the 60% contribution boundary. These six English CSVs are under results/reported/week8. Its three English PNGs are under assets/figures.

The segmentation code joins only the original Telco rows to their Week 7 risk scorecard. It does not join the unrelated support dataset. Value share means share of TotalCharges, not profit. Reported K-Means cluster IDs are arbitrary labels.
